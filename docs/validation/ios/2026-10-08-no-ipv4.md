# 无隧道 IPv4 地址：真机验证

2026-10-08 21:07（Asia/Shanghai），iPhone 11 Pro / iOS 18.5。

## 修改

- `NEPacketTunnelNetworkSettings.ipv4Settings=nil`，删除 `192.0.2.2/32` 和 IPv4 默认路由，仅配置 IPv6 地址。
- 保留全流量 `includeAllNetworks=true`、`enforceRoutes=true`、`excludeLocalNetworks=false`。
- DNS64 仍只在 AAAA 查询需要合成时查询 A 并返回 AAAA；独立 A 查询保留 A 响应。
- DNS 日志使用 trace、事务 ID、client / dns64-A 区分请求；完整逐条记录上游答案、合成地址及 embeddedIPv4、实际下发答案与 UDP 截断。
- IPv4 包若被交付到扩展，记录有界的目的地址/端口/协议日志；新探针明确使用 AF_INET，避免系统自动转换地址带来的误判。

## 结果

主机协议及日志检查 **31/31** 通过；Debug 真机签名构建、安装、启动成功。
使用启动前读取的物理 DNS **10.1.5.1:53**，公网两轮真机 **32/32** 通过（不计两份诊断快照）。

| 检查 | 结果 |
|---|---|
| VPN 外 AF_INET UDP、TCP、绑定 Wi-Fi UDP | 三项回显基线均通过 |
| DNS UDP/TCP、系统域名解析 | 两轮通过 |
| NAT64 UDP 44/1452 字节、同会话连续五次 | 两轮通过 |
| NAT64 TCP 32 KiB 与半关闭 | 两轮通过 |
| IPv4-only HTTPS | ipv4.icanhazip.com 两轮 HTTP 200，DNS 日志确认合成 AAAA |
| 双栈 HTTPS | example.com 两轮 HTTP 200，DNS 日志保留原生 AAAA |
| VPN 内 AF_INET UDP、TCP、绑定 Wi-Fi UDP | 六次 connect 均 errno=51（ENETUNREACH），未出现可通信绕行 |
| VPN 停止/重启 | 两轮通过，结束时 VPN 未连接 |

两份诊断均 `tunnelIPv4Configured=false`、`ipv4Dropped=0`：这些直接 IPv4 请求在 socket connect 阶段被系统拒绝，没有进入扩展的丢包逻辑。
这验证了本设备、本网络和这些探针路径，尚未验证播放器重试、所有第三方应用、蜂窝切换或其他 iOS 版本；并不代表物理 Wi-Fi 接口不再拥有 IPv4 地址。
